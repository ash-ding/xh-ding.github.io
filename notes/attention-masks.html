Attention Masks in the Transformer

Oct 18, 2026 · Reading notes on The Annotated Transformer

The Transformer uses two masks: a source mask of shape (batch, 1, 1, m) and a decoder mask of shape (batch, 1, n, n). This note explains what each one hides, why their shapes differ, and where a causal mask is needed. The whole thing follows from one principle.

1. Where the mask acts

In multi-head attention, the score tensor has shape

scores = Q Kᵀ / √d_k        # (batch, h, n, m)
scores = scores.masked_fill(mask == 0, -1e9)
p_attn = scores.softmax(dim=-1)

Here scores[b, h, i, j] is how much query position i attends to key position j, in sentence b and head h. Wherever the mask is 0, the score becomes −10⁹, so after the softmax that weight is effectively 0. The softmax runs over the key axis (dim=-1), so the remaining visible keys in each row still sum to 1.

  • Mask before softmax, never after. Zeroing weights after the softmax leaves rows that no longer sum to 1, and the masked scores have already distorted the normalization.
  • −10⁹ instead of −∞. If an entire row is masked, −∞ produces 0/0 = NaN. −10⁹ just gives a harmless uniform row.

2. The core principle

A mask is a function mask[b, h, i, j]: "may query i look at key j?"

A dimension needs to be written out in full only if the answer depends on it. Every other dimension is 1 and is broadcast for free.

PyTorch broadcasting aligns shapes from the right and stretches any size-1 dimension to match the other tensor. So a mask only stores the axes along which its value actually varies. The question to ask of any mask is therefore: which of b, h, i, j does "can I look?" depend on?

3. Masks hide columns: sources of information

A column j is a key/value, a source of information. A row i is a query, a consumer of information. Padding masks only ever hide columns, and which columns to hide is decided by the padding of the sequence that supplies K and V.

  • Padding as a key must be hidden. Otherwise real tokens would mix the <blank> vector into their outputs. Worse, a sentence would encode differently depending on how much padding its batch happened to need.
  • Padding as a query is left alone. Its output row is garbage, but nothing downstream uses it. In the encoder, those rows become memory rows, which are masked again as keys. In the decoder, padded target positions are zeroed out of the loss. Masking a whole row would not help anyway: an all-(−10⁹) row becomes a uniform distribution, not "nothing".

4. Source mask: (batch, 1, 1, m)

mask[b, h, i, j] = (src[b, j] != pad)         # depends only on b and j

Whether key j may be seen depends only on whether j is padding:

  • the batch dimension is full, because each sentence pads differently;
  • the head dimension is 1, because all heads share the rule;
  • the query dimension is 1, because every query has the same view (padding is off-limits to everyone);
  • the key dimension is full, because it names which columns are padding.
src            = [[5, 7, 9, 2, 2]]           # pad id = 2, shape (1, 5)
src_mask       = (src != pad).unsqueeze(-2)   # (1, 1, 5)
# inside MultiHeadedAttention
mask           = mask.unsqueeze(1)            # (1, 1, 1, 5) → broadcast to (1, 8, 5, 5)

The same src_mask is used in two places: the encoder's self-attention and the decoder's cross-attention. In cross-attention the scores are (batch, h, n_tgt, m_src), which is not square, yet the mask still broadcasts because its query dimension is 1.

5. Decoder mask: (batch, 1, n, n)

The decoder's self-attention must hide two things, padding and the future:

mask[b, h, i, j] = (tgt[b, j] != pad)  AND  (j <= i)
                    └── b, j only ──┘       └ i, j ┘

The causal rule j ≤ i involves the query position. Position 0 sees one token, position 3 sees four, so rows now differ and the query dimension must be written out. Both axes have length n because queries and keys both come from the target sequence. 

pad_part    = (tgt != pad).unsqueeze(-2)   # (batch, 1, n)   depends on b, j
future_part = subsequent_mask(n)           # (1,     n, n)   depends on i, j
tgt_mask    = pad_part & future_part       # broadcast → (batch, n, n)
# inside MultiHeadedAttention: unsqueeze(1) → (batch, 1, n, n)

Each factor stores only its own dimensions. The & broadcasts them into a mask that depends on b, i and j. Example for [<s>, A, B, <blank>]:

The extra n in the shape comes entirely from the causal rule, not from padding. A target mask with padding only (as in a bidirectional encoder like BERT) would be (batch, 1, 1, n), the same form as the source mask.

6. Cross-attention: target padding hides nothing

In cross-attention, Q comes from the target and K/V come from the source memory, and the mask is src_mask. Consider the two padding cases separately:

  • Source has padding: those source positions are keys, so their columns are hidden.
  • Target has padding: those positions are only queries (rows). No column is hidden, because every source token is real. The padded rows produce garbage that the loss discards: padded targets get an all-zero target distribution and are excluded from ntokens.

7. When is a causal mask needed?

A causal mask prevents one thing: peeking at tokens that have not been generated yet. That can only happen when queries and keys lie on the same sequence that is being generated step by step. In the standard architecture, that is the decoder's self-attention only.

  • Encoder self-attention: the source is fully given, so it is bidirectional.
  • Cross-attention: the source is fully available before decoding starts. Also, j ≤ i compares positions in two different sentences, which share no timeline.
  • Variants:
    • Streaming or simultaneous translation (e.g. wait-k) limits cross-attention to the source prefix received so far. It is the same idea, but the rule is not j ≤ i.
    • Decoder-only LMs (GPT, LLaMA) have only causal self-attention.
    • Prefix-LMs are bidirectional over the prefix and causal over the continuation.

Summary

MaskUsed in"Can I look?" depends onShape
Source maskencoder self-attn, decoder cross-attnis key j padding (b, j)(batch, 1, 1, m)
Decoder maskdecoder self-attnis key j padding and j ≤ i (b, i, j)(batch, 1, n, n)

Masks hide sources (key columns), decided by the sequence that supplies K/V.

A mask stores only the axes its answer depends on. The causal rule is the only one that depends on the query position, and that is why only the decoder mask has a full query axis.

Transformer 中的 Attention Mask

2026 年 10 月 18 日 · The Annotated Transformer 阅读笔记

Transformer 里有两种 mask：形状为 (batch, 1, 1, m) 的源句 mask， 以及形状为 (batch, 1, n, n) 的解码器 mask。这篇笔记讲清楚三件事： 它们各自遮住什么，为什么形状不同，以及什么时候需要因果 mask。这些都可以从同一条原则推出来。

1. mask 作用在哪里

在多头注意力里，打分张量的形状是

scores = Q Kᵀ / √d_k        # (batch, h, n, m)
scores = scores.masked_fill(mask == 0, -1e9)
p_attn = scores.softmax(dim=-1)

scores[b, h, i, j] 表示第 b 个句子、第 h 个头里，query 位置 i 对 key 位置 j 的打分。mask 为 0 的地方，打分被设成 −10⁹，softmax 之后权重约等于 0。softmax 沿 key 维 （dim=-1）计算，所以每一行剩下的可见位置，权重之和仍然是 1。

  • 先 mask，再 softmax，顺序不能反。如果 softmax 之后再把权重清零，每行的和就不再是 1， 而且被遮住的打分已经参与了分母的计算。
  • 用 −10⁹ 而不是 −∞。如果一整行都被遮住，−∞ 会算出 0/0 = NaN；−10⁹ 只会得到一行均匀分布，不会出错。

2. 核心原则

mask 是一个函数 mask[b, h, i, j]，回答"query i 能不能看 key j"。

答案随哪一维变化，哪一维才需要写满；其余维度写 1，靠广播自动复制。

PyTorch 的广播规则是：从右往左对齐，大小为 1 的维度会自动扩展成对方的大小。所以 mask 只需要存储 它的值真正会变化的那几维。看任何一个 mask，只要问："能不能看"取决于 b、h、i、j 中的哪几个？

3. mask 遮的是列，也就是信息来源

第 j 列是 key/value，代表信息的来源；第 i 行是 query，代表信息的接收方。 padding mask 永远只遮列，遮哪些列，取决于提供 K/V 的那个句子里哪些位置是 padding。

  • padding 作为 key，必须遮。否则真实的词会把 <blank> 的向量混进自己的输出； 而且同一句话的编码结果会随所在 batch 补了多少 padding 而变化。
  • padding 作为 query，不用遮。它这一行的输出没有意义，但后面没有任何地方会用到它： 在编码器里，这些行变成 memory 的行，作为 key 时又会被遮掉；在解码器里，目标句 padding 位置的输出在 loss 中被清零。 况且遮整行也没有用：一整行都是 −10⁹，softmax 之后是均匀分布，而不是"什么都没有"。

4. 源句 mask：(batch, 1, 1, m)

mask[b, h, i, j] = (src[b, j] != pad)         # 只依赖 b 和 j

key j 能不能被看，只取决于 j 是不是 padding：

  • batch 维写满：每个句子的 padding 位置不同；
  • 头的维度是 1：所有头规则相同；
  • query 维是 1：每个 query 能看的范围相同，padding 对谁都不可见；
  • key 维写满：标明哪几列是 padding。
src            = [[5, 7, 9, 2, 2]]           # pad id = 2，形状 (1, 5)
src_mask       = (src != pad).unsqueeze(-2)   # (1, 1, 5)
# 进入 MultiHeadedAttention 后
mask           = mask.unsqueeze(1)            # (1, 1, 1, 5) → 广播成 (1, 8, 5, 5)
k0k1k2k3k4
q011100
q111100
q211100

q411100
每一行都一样，所以存一行就够了

同一个 src_mask 用在两个地方：编码器的 self-attention 和解码器的 cross-attention。 在 cross-attention 里，打分形状是 (batch, h, n_tgt, m_src)，不是方阵；但因为 mask 的 query 维是 1，照样可以广播。

5. 解码器 mask：(batch, 1, n, n)

解码器的 self-attention 要遮两种东西：padding，以及"未来"的位置。

mask[b, h, i, j] = (tgt[b, j] != pad)  AND  (j <= i)
                    └── 只依赖 b, j ──┘      └ i, j ┘

因果规则 j ≤ i 用到了 query 位置：位置 0 只能看 1 个词，位置 3 能看 4 个。 每一行的值不同了，所以 query 维必须写满。行数和列数都是 n，因为 query 和 key 都来自目标句。 

pad_part    = (tgt != pad).unsqueeze(-2)   # (batch, 1, n)   依赖 b, j
future_part = subsequent_mask(n)           # (1,     n, n)   依赖 i, j
tgt_mask    = pad_part & future_part       # 广播 → (batch, n, n)
# 进入 MultiHeadedAttention 后 unsqueeze(1) → (batch, 1, n, n)

两部分各自只写满自己依赖的维度，& 一下就广播成同时依赖 b、i、j 的完整 mask。 以 [<s>, A, B, <blank>] 为例：

形状里多出来的那个 n 完全来自因果规则，与 padding 无关。如果目标句只需要遮 padding （例如 BERT 那样的双向编码器），mask 形状就是 (batch, 1, 1, n)，和源句 mask 的形式一样。

6. cross-attention：目标句的 padding 不遮任何列

cross-attention 里，Q 来自目标句，K/V 来自源句的 memory，使用的 mask 是 src_mask。分两种情况：

  • 源句有 padding：这些位置是 key，对应的列被遮掉。
  • 目标句有 padding：这些位置只作为 query（行）出现，不会遮掉任何列，因为源句的每个词都是真实的。 这些行算出的无意义结果在 loss 里被丢弃：padding 位置的目标分布被整行清零，也不计入 ntokens。

7. 什么时候需要因果 mask

因果 mask 只防一件事：偷看还没有生成出来的词。只有当 query 和 key 位于同一条正在逐步生成的序列上时， 这件事才可能发生。在标准架构里，这个条件只在解码器的 self-attention 中成立。

  • 编码器 self-attention：源句是完整给定的，所以是双向的。
  • cross-attention：解码开始前源句已经全部可用；而且 j ≤ i 比较的是两个不同句子里的位置， 它们不在同一条时间轴上，比较没有意义。
  • 变体：
    • 同步翻译、流式识别（如 wait-k）：cross-attention 只能看到目前已经收到的源句前缀。思想相同，但规则不是 j ≤ i。
    • decoder-only 语言模型（GPT、LLaMA）：只有带因果 mask 的 self-attention。
    • Prefix-LM：prefix 部分双向，后续生成部分因果。

总结

mask用在"能不能看"取决于形状
源句 mask编码器 self-attn、解码器 cross-attnkey j 是否为 padding（b, j）(batch, 1, 1, m)
解码器 mask解码器 self-attnkey j 是否为 padding 且 j ≤ i（b, i, j）(batch, 1, n, n)

mask 遮的是信息来源（key 列），依据是提供 K/V 的那个句子。

mask 只存储答案所依赖的维度。因果规则是唯一依赖 query 位置的规则，所以只有解码器 mask 的 query 维是写满的。
